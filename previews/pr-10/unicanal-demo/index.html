Unicanal demo

Registra el estado del día de un chip. Un registro por teléfono y día, como en el portal real.

Cómo se maneja la base de datos

  • Un solo archivo SQLite compartido por dos procesos independientes: el portal web (Flask) y un scraper (Selenium) que actualiza el estado de equipos y campañas.
  • Esquema idempotente: al arrancar cualquiera de los dos se ejecuta CREATE TABLE IF NOT EXISTS y migraciones ALTER TABLE ADD COLUMN guiadas por PRAGMA table_info, así que cualquiera puede iniciar primero sobre una base vacía.
  • SQL plano, sin ORM: cada módulo tiene su repository.py con las consultas, separado de las rutas HTTP.
  • Registros por día: los bloqueos son un registro por teléfono y fecha (UNIQUE (telefono, fecha)), solo se agregan.

Cómo se hace la reportería

  • Una vista SQL central, combined_report, une las tablas de teléfonos, equipos y el bloqueo del día. Casi todos los reportes, el dashboard y las alertas leen de ella, no de las tablas crudas.
  • Los reportes son tablas filtrables exportables a CSV/Excel (pestaña Reportes).
  • Las alertas persistentes son reglas evaluadas sobre esa vista tras cada ciclo del scraper: se abren al cumplirse la condición y se cierran solas cuando los datos cambian.
